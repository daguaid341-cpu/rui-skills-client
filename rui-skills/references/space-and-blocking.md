# 空间与人物调度

真人与漫剧共用。排镜前在内部完成：剧情冲突 → 实际空间 → 人物目标与控制权 → 触发和调度 → 镜头设计 → 连续性复核。与[叙事镜头设计](narrative-camera-design.md)配合；不要求每次交付空间表。

## 事实、设计与缺口

- 原稿事实与已确认资产：事件、对白、出入场、关键结果、道具归属、空间结构和揭示顺序保持不变。
- 导演设计：在已知空间和已有动作内设计取景、机位、焦点与运动，不改变事件及人物状态。原稿未明确而本次必须明确的位置、手位或衔接，先提出最小必要问题；不先编定站位或动作。用户确认的补充才可落入方案，不能声称已从未查看的参考图看见。
- 实质缺口：资产与原稿矛盾，或某个未知位置会改变事件结果、逃生条件、人物知情范围时，保留可完成部分，提出最小必要问题。不能用假出口、暗号或新增道具解决矛盾。

## 从真实空间到控制关系

按实际到达的位置区分建筑、室内外、房间与走廊、上下层以及回忆。保留原场号，在规划记录中用子空间后缀区分；内部 JSON 继续使用现有合法 sceneId 和 sceneIndex，不把自定义子空间号直接塞进协议字段。实际换景开新段。

每个涉及的空间确定必要出入口、两至四个有用锚点、相邻空间连接、威胁方向以及在场/画外人物。锚点优先取已有门窗、柜台、车辆或剧情道具，不为填表增建空间。已知资产结构优先。

围绕本场争夺的出口、物件、通行权、保护对象或发言权回答：角色想去哪里？谁或什么挡住他？谁能移动、谁受到限制？什么事件使原位置改变？结束时谁与谁同侧、谁被隔开？重要站位应有动机，不只分配画面左、中、右。

关键调度写成：**初始位置与持物 → 已有触发 → 路径、接触或遮挡变化 → 结束位置与关系**。距离优先使用一臂、半步、门内一步等可读关系；估距注明是设计值。没有移动依据时保持原位，不为丰富机位补动作。

## 路线与困局同时检查

人物必须能沿可见或已交代的通路抵达目标；这条通路也不能让原本受困的角色早就能够安全离开。例如援助者能进入走廊时，先判断主角此前为何不能沿同一路线撤离；只有原稿已有的敌方转向、封锁解除等事件能解释通路变化，不能凭空补一次让路。

实体方向与画面左右分开：反打可以改变画面侧，但门窗不能换墙、道具不能换手。摄影机用固定锚点定位，保持关系轴同侧；人物移动改变轴线时，用允许的取景或连续运动建立新关系，普通道具插镜不能自动解决越轴。裁掉某人不等于该人离场。

30秒仅为每组时长上限，不按首组或后续组限制景别。关键路线与关系按本场观看重点选择取景，分组不改变空间或动作状态；用户明确限定本次拍法时遵守其范围。

## 信息与连续状态

内部区分实际事件、每个有关角色已知信息、观众已见信息。怀疑不等于确证，某人发现线索不等于同场所有人知道；创作者知道的反转不能提前拍出。只追踪本段相关的信息，不引入其他作品的人名、集数或设定。

将位置、朝向、视线、左右手、道具归属、衣饰伤势、门窗损坏与持续动作阶段传到下一镜/段。检查动作是否缺步、重复或需要同一只手同时做不相容的事；新设计不能恢复损坏物或消除伤势。

## 落入现有输出

内部方案写入现有 segment.blocking、cut.shot、cameraPosition、eyeline、focus 和必要 note；统一提示词仍不写人物站位。首镜说明本段起点，后续镜头只保留有变化或易错的承接，每个独立提交段保留必要信息。原稿事实与导演安排的区分放在交付说明，不把长检查表塞进生成提示词。

用户只要调度时输出空间、调度及结束状态；只要提示词时将必要关系融入镜头。检查以是否看懂事件和关系为准，不以站位数、运镜数或表格填满为准。

需要将站位、路线和机位画出来时，按[本地站位图](blocking-diagrams.md)整理米制空间数据。先检查有标注俯视图，再查看无标注机位图；实际看图后才能记录视觉通过。自动几何检查不判断叙事动机、景别限制或真实人体接触。
