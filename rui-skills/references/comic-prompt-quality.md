# 漫剧提示词质量

mode=comic 时排镜和交付前读取。本文件补充漫剧画风、动画和验收，叙事、空间、对白、时长与用户指定机位规则仍共用。引擎整理与导出助手写入的内容，不会自动创作高质量动画。

## 先锁定一种表现方式

优先使用用户指定或实际参考图中的二维赛璐璐、三维卡通、水墨等表现方式。没有指定时可按引擎默认二维动漫先写文字方案，注明默认，不声称看过参考。production.style 填具体画风；各独立段用 segment.unifiedPrompt 写清本段表现方式，避免旧项目级真人提示词覆盖漫剧模式。

- 二维：保持线条粗细、轮廓、头身比例、固有色与上色方式，明暗变化服从场景光源；不默认加入真人毛孔、皮肤绒毛、实拍演员或多套摄影机型号。
- 三维：保持模型比例、材质、绑定形变和渲染方式；不自动套二维线条、平涂，也不因“电影感”改成真人。
- 特定风格：沿用已给笔触、阴影与材质，不无依据混合水墨、赛璐璐、写实皮肤和塑料高光。

机位、景别、景深及运动可以用于虚拟摄影。用户明确指定的设备或光学效果仍保留为参考，写清所需效果；共用的真人肤质与人像默认值不自动追加到漫剧。空间和手部接触需要清楚时，不能用统一浅景深虚化关键内容。

引擎现有 comic 默认偏二维；自定义三维等风格时，完整导出的通用“线条、色板、上色”约束需按实际画风人工复核。修改本段显式提示词，不依赖 mode 自动清除遗留真人内容。

## 让动画描述能执行

先写本镜观众必须看到的变化，再写已有动作的起点、过程、接触点和结果。镜头运动不能替代角色动作；运镜推近一张静态表情图，不代表完成了交接、开门或转身。

二维动画尤其检查轮廓可读、肢体交叠、前后遮挡和物件接触。交接应明确谁先持有、何时对方接稳、何时松手；只演一次，不把准备、接触、完成挤成无法辨认的瞬间。仅细化原稿动作，不为了动画感新增反应。

可用现有可选 cut.animation 写已有动作的动画过程，用 cut.visualTreatment 写与当前画风一致的局部处理。这两项会进入 Rui 文本导出，但不能假定所有底层协议导出都携带；下游必需的信息同步到 cut.shot，逐条检查实际导出。不要只写“动作自然流畅”“表情生动”。

速度线、冲击帧、残影、夸张变形、Q版切换和定格只在用户/剧情画风允许且确有叙事用途时使用。不能靠它们隐藏接触错误、增加实体人物、提前揭露信息或省略动作结果；不自动加漫画格、气泡、屏幕文字、配乐或冲击音。

画内对白写清姓名、对象、语言、原词和语气；画外声音注明来源，非说话者不对口型。镜头内对白与动作能否并行应具体判断，不用固定秒数均分所有内容。

## 导出后的实际检查

逐段查看真实导出的文本，不以 JSON 校验代替阅读：

1. 本段表现方式是否唯一、具体，与参考一致；是否混入真人模板或其他段的设定。
2. 用实际姓名区分角色和声音；若只提供 script/storyboard，导出可能保留 C01 等编号，最终稿须依据已知映射补全，不猜姓名。场景编号同理。
3. 关键动作、交接归属、末帧和下一段起点是否一致；不得因分组重演动作。
4. 具体画面、动画、声音和完整对白是否能在估算时长内完成；长镜必要时延长，不删词或强行加速。
5. 机位、取景、关键焦点和声音是否独立可理解；内部协议的通用身份不替代最终稿的角色实名。

检查结果分开报告：文本审阅、引擎结构检查、实际配音、视频视觉验收。未生成视频时，最多判定“提示词可进入试生成”，不能判定画风稳定、口型、运动、角色一致性或成片质量已过关。测试样稿标明合成数据，不能冒充用户已经使用过的作品。
