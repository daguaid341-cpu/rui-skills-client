# 最终视频提示词

本文件用于真人剧与漫剧的最终提示词编写和导出；内部数据契约、剧情校验及原始台词保持完整。漫剧同时执行[漫剧提示词质量](comic-prompt-quality.md)，检查显式 unifiedPrompt 是否携带过期真人风格，不能仅切换 mode 就认为已经清除。

## 默认参考素材齐全

默认人物、场景、道具参考图已经齐全，按这一前提直接写视频提示词，不反复询问是否有图，不展开外观清单，不自行设计服装、配饰、家具或装修。素材职责只说明一次：角色图承接身份与外观，场景图承接空间布局，道具图承接造型；具体表演、取景和运动由本镜决定，不照搬设定图的排版。

这是写作前提，不是已查看或已上传素材的证明。只能使用真实提供的角色/场景名称、ID或已知附件引用，不虚构图片编号、绑定关系或视觉观察。用户明确说明缺图时再按实际情况处理；实际生成时核对真实附件，不能用文字ID冒充图片上传。已有编号不必为了精简而删除。

## 内部完整，输出精简

内部保留角色关系、知情范围、场景坐标、轴线、道具归属、受光关系、动作起止状态、对白与时长检查。不要把检查表、反馈统计、整剧摘要或每个JSON字段都写进最终提示词。

默认输出：本段参考素材职责、一次统一风格与声音要求、逐镜景别/必要运镜/主要动作和可见反应、少量本段关键约束。每镜先确定必须让观众看见的事件，再选信息；不能按字数截断、删台词、删剧情转折或删关键道具状态。原台词逐字保留。

排镜执行[叙事镜头设计](narrative-camera-design.md)。最终逐镜沿用剧本角色实名，明确必要的拍摄方向、过肩前景、正反打对象、视线与功能性取景范围；这些信息属于叙事内容，精简时不得删除或统一改成“平视”。人物之间的平视与摄影机角度分别表达。

镜头设计范围保持开放：按本镜叙事需要选择景别、方向、高度与角度、人物拍摄关系、运动、焦点及构图，不将侧面、斜侧、过肩或正反打写成固定菜单。最终只表达本镜已经选定的拍法及必要信息，不复制整张镜头类型表。更细的近景或中近景取景、组合运动的起止和焦点变化在影响理解时写清；精简不抹去这些设计，也不因增加类型而新增剧情或表演。所有选择仍服从对话轴线与跨组景别限制。

同时落实该参考的侧面方向与跨组景别规则：写清人物朝向和摄像机相对方向，不能仅列景别；超过30秒的连续任务中，首组优先全景、中景，后续组禁用全景、中景。内部保留实际组序，按本组适用范围检查`size`、`frame`、`shot`和最终文字；必要的本组限制可写入`segment.constraints`。精简和完整导出均不得省略已设计的方向或重新加入禁用景别，中间稿遗漏时依据已确定设计修正，不猜测人物站位。

台词镜头还须落实已确定的对话机位：用角色实名写明谁对谁说话、讲话者面向与视线对象，镜头从被讲话者这一端拍向讲话者；有过肩或斜侧时，写清实际前景人物和轴线同侧的取景方向。反打保持方位对应，反应镜保留真实画外说话者且听者不对口型。这些信息写入相关镜头正文，在精简稿中同样保留，不用“按轴线处理”等笼统指令替代本镜实际拍摄关系。

为每段填写可选 `segment.unifiedPrompt`（含本段必要共享要求），导出时它覆盖项目级 `storyboard.unifiedPrompt`；旧项目未填写时仍沿用项目级内容，不猜测删减。统一提示词只包括当前独立提交段需要的信息，不反复写未来段落、其他时态和无关角色；跨段连续性留在内部状态表。各段独立提交时重复必要设定，同一段内部去重。不要靠一长串摄影设备与质感词替代明确的主体、光照关系和动作。

用户指定的摄影机、镜组、焦距、光圈和特殊拍法必须保留。共同摄影基准写一次，变化写在对应镜头。构图、视线、焦点和稳定性只有在影响理解、明确指定或容易出错时才展开；手部道具特写、拉焦目标、看向第三人的方向等不能省略。最终只需在生成稿表达的信息应先写入shot，其他必要补充可保留在专用字段；不要给每镜机械套用同一字段内容。

## 每段提示词独立可用

生成AI只会收到当前独立提交段的提示词和实际附上的参考素材，默认不会收到源剧本、人物小传全文、历史聊天或其他段。每段写清理解画面与表演必需的情境、角色关系、动作对象与先后顺序，以及说话者、台词语言和完整台词；必要背景仅从用户已提供材料提炼，不复制全剧摘要，不新增剧情、动作、道具或未知手位。

区分内部审核与最终生成指令：核对源剧本、逐字保留对白的要求留在内部流程；最终说明不能用“原文”“原句”“原有动作”“依原顺序”“按人物设定”等指代生成AI未收到的材料。直接写出需要执行的动作、视线对象和语气，而不是只删除这些词。可以引用本段确实列出的“下列台词”、镜头编号及实际附图。此限制只针对指令说明，不能据此删改对白中人物说出的原句。

声音要求必须明确声音内容、声源或说话者、触发时机与必要的远近变化。不要使用“保留原文动作对应的声音”“清楚的原对白与原动作对应的现场声”等笼统表述，也不要替换成同样含糊的“自然音效”。将本段已有事件写成具体指令，例如本段有电梯到站、门扇运动和角色走出时，写“到站时响一声叮；门扇运动时有机械声；角色走出时有同步脚步声”。示例不是每段固定添加的音效清单；不添加本段没有依据的铃声、动作声或配乐。

直接列出本段对白及语言，写清画内说话者、画外声音来源和非说话人的口型要求。同一段的声音要求写一次，避免统一提示词与soundscape机械重复。凡支持生成所需的信息未在本段文本或实际附件中出现，应先补齐有材料依据的信息；无法确定而确实必需时询问用户，不凭空补写。

## 表演与描述限制

按本场动机与触发信息设计少量可见反应，交代对象和先后关系，不默认每镜同时写低头、抬眼、眨眼、吞咽、呼吸、握拳等动作。没有动作依据时不要凭空增加接触、眼泪、台词或人物动机。

功能性面部特写只放大已有行为的情绪、眼神与语气，不授权补入小动作。下列情绪示例仅用于理解材料已经出现的表现，不从清单为角色追加行为；用户明确限制不得新增动作时优先执行。不能为特写新增人物已知信息、将说辞拍成真实经历或提前泄露后续真相。

最终画面和表演描述禁止用生理变色表达情绪，包括眼睛/眼眶/脸色发红、脸颊泛红、满脸通红、面红耳赤、眼睛充血、脸色苍白或铁青、指节泛白，以及眼神冒火等近义写法。统一按上下文改成可见行为，不把禁词重新列进负面提示词。

- 愤怒：可选下颌绷紧、盯住对方、原本松开的手握紧。
- 悲伤或委屈：可选垂下视线、嘴唇轻颤、话到一半停住。
- 害羞或窘迫：可选避开目光、抿唇低头、短暂停顿后看回对方。
- 惊惧：可选呼吸一顿、动作停住；后退须符合站位与剧情。
- 情绪不明：使用表情短暂凝住或目光停顿，不擅自判断悲伤、愤怒或羞怯。

以上是选择依据，不是每次自动添加的动作套餐。角色原有眼睛/皮肤颜色、服装颜色和真实环境光源颜色不受这一情绪描述限制；不要借替换改变资产。台词中人物说出的原句不是画面描述，必须逐字保留。引擎会对常见中文变色短语做保守的导出替换，但不具备完整语义理解，助手仍需在导出前结合剧情改写、导出后通读验收。

## 节奏与交付检查

默认按剧情使用可变时长，每组不超过30秒，内部依照对白、动作、停顿及反应分配时长，不机械每镜5秒。默认精简稿按镜头顺序表达；用户指定或目标协议需要时输出秒数。H3的时间与图片对齐要求继续遵守，不因精简破坏协议。

交付前检查：单独复制当前段及其实际参考附件后，是否仍能明确理解角色、动作、对白、表演和声音；是否残留对未提供剧本、人物小传或其他段的隐含引用；重要动作是否清楚；参考引用是否真实；声音、运动、焦点与曝光要求是否相互矛盾；全局与逐镜描述是否重复；历史修复条款是否与本场无关；是否残留生理变色描述。完全锁定不晃动与手持微晃有冲突，但固定机位本身不等于禁止手持。

## 导出

`export-text` 默认精简稿，按镜头顺序输出；`--detail full` 输出完整摄影字段并默认显示秒数；`--timing sequence|seconds` 可单独覆盖时间标记。两种模式使用同一份已校验资料，均默认参考图齐全并处理生理变色描述，不改写源JSON。

只把当前段特有的关键限制写入可选 `segment.constraints` 字符串数组。既有结构化字段仍用于检查；精简导出保留具体机位、道具焦点和非默认视线，合并相同摄影基准与共同备注，省略普通三分法、普通主体面部焦点和stable等泛化字段。若用户明确指定普通字段也必须显示，将其写入镜头正文或使用完整稿，不能因默认去重丢失要求。

导出后核对叙事机位与镜头正文：过肩人物、反打关系、侧面或斜侧方向、功能性面部取景与关键道具焦点均须保留。若中间稿遗漏，依据已完成的镜头设计补回并检查一致性，不重新猜测站位或动作。字段结构通过不等于镜头设计通过，执行叙事镜头设计中的交付复核。

实际验收分别记录画面观感、动作完成度、人物一致性与真实尝试次数。需要比较长短稿时使用相同素材、模型和设置；没有实际生成只能报告文本/程序验证，不能宣称画质提升。

最终交付沿用[紧凑节奏与交付](storyboard-pacing.md)：默认Word、原台词语言和自然段落；精简指提示词的信息密度，不改变交付格式。统一提示词不包含人物站位，位置与道具状态放到相关镜头的动作起点和衔接。既定摄影参考写一次，实际单镜设备参数保持自洽。
