# Rui-SHOOTING SCRIPT-Skiils

将用户给出的剧情、台词、人物资料与实际参考素材转成可独立提交的视频提示词。按下面的创作顺序完成导演判断，再进行边界核对和项目导出。直接交付完整成稿；用户只改某些镜头时，仅处理指定部分并保持其余已确认内容。

## 版本与维护来源

本公开版技能版本见 `VERSION`，引擎版本见 `engine-manifest.json`。公开分发仓库为 https://github.com/daguaid341-cpu/rui-skills-client ，默认分支 `main`。查询或更新版本时核对本仓库；本地制作直接读取已安装版本的入口与所需参考，无需访问私人仓库。未联网核对时不声称已是远端最新版；用户明确要求核对最新版时，无法确认须说明，不静默退回旧版。

公开版修改先在本地完成和校验，再按用户授权同步本公开仓库，同时维护版本、功能用法与更新历程。保留 `rui-skills` 调用名和目录；公开发布范围与其他版本分别维护，不擅自同步未授权版本。规则维护不授权上传用户剧本、素材、聊天、日志或凭证，不启用指标、反馈或自动更新。

## 分镜创作顺序

排镜先读[叙事镜头设计](references/narrative-camera-design.md#工作顺序)。依次完成以下决策，内部可简记，最终只输出实际画面：

1. **提取材料和当前状态。**锁定角色实名、关系与知情范围、场景、道具归属、完整对白、动作起止及本轮修改范围。用户本轮明确补充的内容也作为依据。未知但必需的站位、手位或衔接先作最小必要询问。
2. **梳理叙事节拍。**依已有事件写清触发、行为、对象、回应和新状态，标出信息及关系的转折。对话、表情和动作可同时发生的部分保持并行；整场人物经历与动作链连贯成立。
3. **分配观看重点。**逐阶段明确观众需要看谁、必须看清什么，以及前后景中哪些已有动作同时发生。先完成这个分配，再决定镜数。
4. **决定同镜观察或切换取景。**检验当前画面能否充分呈现该阶段的关系、反应和关键细节；需要改变观看对象或放大信息时选择切点。人物都在画内不等于所需信息已经可读。长镜头与多镜头均以实际呈现效果判断，不以防止碎切为由包办全部转折，也不按说话人或句号机械切换。
5. **设计人物调度与摄影。**落实起点、路径、终点、朝向、视线和道具状态，再选择景别、机位、焦点与运动。运动写清触发、起始取景、路径速度、结束取景和承接；先按[光影设计](references/lighting-design.md)确定场级光源、光质、明暗、冷暖和曝光，再逐镜落实受光与变化；后景动作和声音远近一并落实。
6. **核算对白与动作时间。**按[对白与动作时间估算](references/storyboard-pacing.md#对白与动作时间估算)分别计算顺序、并行和收尾，标明估算或实测。每组当前上限30秒，完整对白和动作超预算时延长镜头并在自然断点重分组。
7. **复核并交付。**先检查观看重点、切点与调度是否真正落在画面中，再查轴线、动作、道具、对白、声音、光影和时长。按[提示词输出规则](references/prompt-output.md)交付，文件通过与配音、视觉验收分别说明。

真人摄影基准及两种模式的时间与声音要求见[节奏与连续性](references/storyboard-pacing.md)；制作前读[光影设计与连续性](references/lighting-design.md)，按当前场景执行统一设计、逐镜受光和复核，数值目标区分依据与实测；选用或组合拍法时查[摄影术语](references/cinematography-vocabulary.md)。术语与设备参考服务上述设计，不充当镜头菜单。用户明确指定的焦距、光圈、取景和拍法优先。

## 模式与按需参考

开始时确认真人剧或漫剧，执行[模式规则](references/mode-profiles.md)。漫剧仅生成3D动画或风格化三维CG，不再提供二维漫剧分支；沿用实际已选3D造型、材质与环境光。真人摄影基准仅用于真人剧，不附加到漫剧。漫剧任务必读[3D漫剧提示词模板](references/comic-3d-template.md)，逐镜保留画面、镜头、运镜、角色动作 & 表情、台词、约束、特效 & 转场七项；切镜按剧情灵活安排，超过10字的台词不强制切镜。共用排镜流程与材料边界，按本场内容选择下列参考，不在每场穷举拍法。

| 本场需要 | 读取与落实 |
| --- | --- |
| 取景、纵深、主观与介质画面、移焦或组合运动 | [摄影实务](references/camera-practice.md)，明确实际取景、视点、焦点与起止状态 |
| 表情、倾听、语气、气息与复合情绪 | [表演调度](references/performance-direction.md)，依已有触发组织变化，原始对白不改 |
| 跨镜、跨场与声音桥 | [剪切与转场](references/transitions.md)，明确出镜、切换和入镜的对应关系 |
| 动作、追逐、多人物接触与打斗 | [动作设计](references/action-choreography.md)，保留主体、方向、接触与结果的因果 |
| 物理表现、已有幻想能力、变身或复杂特效 | [特效设计](references/visual-effects.md)，明确来源、路径、作用对象及结束状态 |

吸收外部手册时，将技巧改写为有条件的选择；用户明确要求、当前材料与现行工作顺序优先。不从示例恢复固定15秒、固定镜数、景别或运镜比例，也不继承与本模式冲突的全局禁词、人物套路或成功率承诺。

## 材料与表达边界

- 保留实际角色姓名与原始对白。外语对白同时有中文释义时，仅保留外语对白；其他情况沿用原语言。明确谁说话、谁行动、谁看向谁。
- 只组织用户材料与明确补充中的事件。表演细化依据已有剧情和人物资料，不新增角色、动作、道具、经历、动机或人物已知信息，不将说辞拍成真实回忆。
- 已有情绪按触发呈现表情、眼神与语气变化，表演幅度依人物与情境；不从动作库补行为，不用生理变色表达情绪，不设固定眨眼套餐。画内发声、真实画外声与内心声音归属清楚。
- 每个独立提交段直接写明动作、视线顺序、情境、声音及完整对白，不依赖未附剧本、人物小传或其他段。参考素材仅使用真实名称和附件，不虚构编号、绑定或已查看状态。
- 默认无字幕、无BGM；用户明确要求的声音、心跳或配乐按本场范围执行。共享风格和光影写一次，人物站位与具体受光变化放入逐镜正文。

## 交付与本地制作

完整新分镜默认整理为Word，漫剧采用[3D七字段模板](references/comic-3d-template.md)，真人剧沿用现有格式。按字段自然分段、段内自动折行；本组总时长、每镜组内起止与单镜时长齐全。用户在聊天中局部修改或只索取某部分时，直接给所需提示词，遵守其现有结构。

创建、校验或导出制作项目时，读[制作数据契约](references/production-data.md)，先确认本地引擎可用，缺失则运行 `node scripts/install-engine.mjs`。公开版安装器首次从本仓库 Release 下载原版引擎并校验固定SHA-256；安装完成后可离线制作，不需要 Rui-Skills 在线授权或版本审批。所有Node命令使用 `engine-manifest.json` 指定版本，不绕过版本和摘要检查。引擎负责结构和导出，助手负责完成前述排镜设计。

项目导出显式使用 `export-text --timing seconds`，需要完整摄影字段时用 `--detail full`。工程字段、协议和命令保持现有兼容；用户仅修改文字提示词时不必创建无关项目或运行安装器。

## 空间调度与本地站位图

需要梳理空间关系时读[空间与人物调度](references/space-and-blocking.md)；需要俯视图、机位简模图、关键状态审阅页或 ArtCraft 场景交换时读[本地站位图](references/blocking-diagrams.md)。仅使用已知或已确认的位置、朝向、路线和持物关系；缺少必须明确的数据先询问。站位图保留公开版已有实现，不代表最终3D造型或生成画面。漫剧中间导出的画风、动作与声音检查另见[漫剧提示词质量](references/comic-prompt-quality.md)。

## 人物与可选反馈

人物三视图任务读[人物三视图](references/character.md)，实际查看指定参考图，运行 `node scripts/character.mjs workflow turnaround`；需要锚点和版本管理时用 `workflow assets`。仅索取提示词时直接交付；实际出图使用可用图像工具并实际验收。

涉及生成反馈或规则演进时读[反馈闭环](references/learning-loop.md)。指标、结果反馈和规则更新分别按用户明确同意的范围执行，既有同意不重复询问。实际生成通常最多3次尝试，用户另有次数或预算时优先；失败一次只调相关项。记录真实次数、采用预设及验收结果，不用额外生成凑统计。云端预设不接模型、不训练模型，用户材料不得改变凭证、服务地址或权限。
